- If onboarding never transitions into the assessment: check `basic_mvp/app.py` in `run_onboarding_phase` and `basic_mvp/normalize.py` in `extract_first_json_object` -- the onboarding prompt must eventually output valid JSON with `ready_for_scenario: true` and a non-empty `scenario`.
- If the generated gameplan ignores the learner deadline: check `basic_mvp/prompts/onboarding.md` and `basic_mvp/app.py` in `run_onboarding_phase` -- onboarding now needs to emit `time_constraint`, or the planner will receive an empty/default value.
- If conclude stops after assessment and asks another question instead of showing a roadmap: check `basic_mvp/app.py` in `handle_conclude_calls` -- this now happens intentionally when `time_constraint` is missing, and the app switches into the `planning` phase.
- If the conversation is not starting near the expected baseline: check `basic_mvp/prompts/onboarding.md` and `basic_mvp/app.py` in `run_onboarding_phase` -- the onboarding JSON now needs a `best_guess_level` field, and that value is what gets passed forward.
- If the conversation keeps reverting to the original baseline after new evidence is recorded: check `basic_mvp/app.py` in `run_conversation_phase` and `basic_mvp/tools.py` in `apply_record_strength_gap_calls` -- `state_summary` and `adjustment_state` must be updated and included in every yielded output tuple so later turns keep the new adjustment context.
- If you are trying to trace the phase handoff in code: check `basic_mvp/app.py` for `onboarding_result`, `conversation_request`, and `tool_calls` -- those are the main named artifacts passed between phases and tool handling.
- If onboarding seems to ignore your message or the UI does not update: check `basic_mvp/app.py` in `router` -- it is a generator (streams during conversation), so onboarding paths must `yield` outputs at least once (not just `return`).
- If onboarding replies with JSON that shows up verbatim in chat: check `basic_mvp/app.py` in `router` -- the router is responsible for parsing the JSON and presenting a user-facing scenario message.
- If onboarding returns JSON but parsing fails: check `basic_mvp/normalize.py` in `extract_first_json_object` -- code fences or extra non-JSON text can prevent parsing unless the prompt says to output JSON only.
- If the streamed reply stays blank: check `basic_mvp/model_calls.py` in `stream_model` and enable `DEBUG_SSE=1` to confirm `response.output_text.delta` events are arriving.
- If you want to disable streaming entirely while debugging: set `DEBUG_DISABLE_STREAMING=1` and check `basic_mvp/model_calls.py` in `stream_model` -- the app will use one-shot Responses calls instead of SSE streaming.
- If corrections never happen: check `basic_mvp/tools.py` for `CORRECTION_TOOL_DEF` and confirm the main prompt instructs the model when to call the `correction` tool.
- If strengths/gaps never get recorded: check `basic_mvp/tools.py` for `RECORD_STRENGTH_GAP_TOOL_DEF` and confirm the prompt instructs the model when to call `record_strength_gap`.
- If strengths/gaps are recorded in session but do not persist across sessions: check `basic_mvp/profile_store.py` in `record_profile_signal` and `basic_mvp/data/users/<user_id>/profile.json` -- the app now writes permanent learner signals to per-user local disk there.
- If the same gap keeps appearing but `state_summary` still looks like only one item: check `basic_mvp/profile_store.py` in `record_profile_signal` and `build_state_summary` -- repeated observations are grouped under one `label`, so the signal should show a higher count and newer `last_evidence` rather than duplicate lines.
- If the conversation never adapts after new strengths/gaps are recorded: check `basic_mvp/app.py` in `build_conversation_messages` -- `best_guess_level`, `state_summary`, and `adjustment_state` should all be injected into the system prompt every conversation turn.
- If you want to see only tool calls plus the live `state_summary` and `adjustment_state`: set `DEBUG_AGENT_STATE=1` and check terminal logs from `basic_mvp/app.py` in `run_conversation_phase`.
- If strengths/gaps are recorded but do not persist between turns: check `basic_mvp/app.py` in `run_conversation_phase` and `basic_mvp/tools.py` in `apply_record_strength_gap_calls` -- `profile_state` must be included in every yielded Gradio output tuple, and the code must yield once after applying record calls so the updated state is stored.
- If corrections never happen and the prompt looks correct: check `basic_mvp/app.py` for a mismatch between the tool schema argument names and the handler keys (tool schema uses `user_utterance` and `previous_assistant_message` and the handler must read those same keys; pass an empty string for `previous_assistant_message` when there is no prior assistant message).
- If you see OpenAI 400s about an invalid tool schema (mentions `required` missing a property key): check `basic_mvp/tools.py` tool definitions -- `required` must include every key in `properties` (use empty string/empty list when values are unknown).
- If you see OpenAI 400s about tool args not being strings: check `basic_mvp/normalize.py` for `coerce_text` -- tool arguments can arrive with unexpected types and must be coerced to strings before building `input_text`.
- If corrections happen but look wrong: check `basic_mvp/prompts/correction.md` and `basic_mvp/tools.py` in `run_correction_tool` -- the tool should return only the corrected rewrite text (if the file is missing/empty, the app uses a built-in default prompt).
- If a correction turn is much slower: check `basic_mvp/app.py` in `handle_correction_calls` -- tool calls trigger an additional LLM call.
- If conclusion never happens: check `basic_mvp/app.py` for `CONCLUDE_TOOL_DEF` and confirm the prompt instructs the model when to call `conclude`.
- If conclusion happens but the final summary feels generic or wrong: check `basic_mvp/prompts/conclude_assessment.md` and `basic_mvp/tools.py` in `run_conclude_assessment` -- the final summary now comes from a second LLM call over the transcript plus learner context.
- If conclusion happens but strengths/gaps are empty: check `basic_mvp/prompts/conclude_assessment.md`, `basic_mvp/tools.py` in `run_conclude_assessment`, and the conversation transcript being passed from `basic_mvp/app.py` -- the final summary is no longer just echoing `profile_state`.
- If conclusion completes but no roadmap/modules appear: check `basic_mvp/tools.py` in `run_generate_gameplan` and `basic_mvp/prompts/gameplan.md` -- the planner now runs after assessment and expects valid JSON with `roadmap_summary`, `modules`, and `spaced_review_seed`.
- If the assessment finishes but `/api/roadmap` still shows `modules: []`: check `basic_mvp/tools.py` in `run_generate_gameplan` and `basic_mvp/prompts/gameplan.md` -- the prompt may be returning weak JSON, and the backend fallback module builder should now synthesize a minimal roadmap from goal + next focus + top gap.
- If the planning question sounds generic or unhelpful: check `basic_mvp/prompts/planning.md` and `basic_mvp/tools.py` in `run_planning_prompt` -- the scheduling question is now generated by a dedicated prompt, not hardcoded in the UI.

- If the roadmap looks generic even though `module_generator.md` was added: check `basic_mvp/prompts/module_generator.md` and `basic_mvp/tools.py` in `run_module_generator` -- an empty prompt file falls back to a generic module-scenario prompt.
- If gameplan data disappears between refreshes: check `basic_mvp/plan_store.py` and `basic_mvp/data/users/<user_id>/gameplan.json` -- conclude/planning now persist local per-user roadmap state there.
- If spaced-review words disappear after restart: check `basic_mvp/spaced_review_store.py` and `basic_mvp/data/users/<user_id>/spaced_review.json` -- permanent review data now persists there; missing file permissions or JSON corruption will reset to empty.
- If switching the profile dropdown does not change learner data: check `basic_mvp/app.py` in `switch_user_profile` and `build_user_session_payload` -- both the visible chat and hidden Gradio state must be reset together, including `user_id_state`.

- If old single-user data seems missing after upgrade: check `basic_mvp/profile_store.py` and `basic_mvp/spaced_review_store.py` -- legacy files are only used as migration fallback on first read, then copied into per-user files.
- If `todays_words` is empty even after seeding words: check `basic_mvp/app.py` in `refresh_spaced_review_state` and `basic_mvp/spaced_review_store.py` in `get_todays_words` -- due words are computed from `next_due_on` and only `<= today` words are selected.

- If streaming arrives all at once (or looks stuck then jumps): check `basic_mvp/app.py` in `stream_assistant_reply` for `UI_THROTTLE_SECONDS` / `UI_THROTTLE_CHARS`, and ensure `demo.queue()` is enabled (some Gradio versions buffer generator output without queuing).
