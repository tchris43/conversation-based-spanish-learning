So I used myteam to build a better workflow for writing new components. I created a dev role that would implement the plan from the orchestrator while making auditing comments and debugging logs and then delegate to the preDebugging role that looks at the auditing comments and debugging logs and checks for anything that should be debugged so that it is like defensive programming. Then I also created a role for optimizing the LLM calls and agentic systems. I also created a skill that talks about how the UI should be designed or edited so that it stays simple and looks good and fits the theme of my app.

I learned that it is important where you put roles or skills. I originally had the optimizer under the predebugger and then moved it to the root because I didn't want it to have to go through the full flow everytime I used the debugger. However, I then moved it back to the bottom because I realized that going through that flow each time I edited code was actually very beneficial. 

I used myteams to work on improving the latency of my LLM call and it gave me some options that were a lot more careful and wouldn't break my code. I also had it update the UI to feel more in line with my app, and it knew exactly how to do it.
